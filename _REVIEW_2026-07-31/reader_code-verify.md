All checks performed on the local checkout at `/home/user/ATR_research` (branch tip `eb86404`, identical to main). ## SUMMARY

The project's headline quantitative claims are overwhelmingly supported by the committed artifacts — better than typical for a fast-moving multi-agent repo. I independently reproduced: the EXP_010b reproduction gate (25/25 exact match against the Stage 1 record inside the committed `_DATA` zip), the EXP_012m census verdict (zero lens-dominant layers under the pre-registered rule, recomputed from raw per-prompt ranks; multi-hop hit@10 max 0.97% logit-lens / 0% J-lens), the permutation-test table, the full/scan/infill terminal inventories, the EXP_010d basin-comparison ARIs and threshold sweep, and the EXP_010b energy ratios and lag-scan signatures — all match to the printed precision.

Two genuine problems surfaced. (1) **RESULTS_EXP010B.md contains five numbers that match no committed artifact**: the SB basin-size tuple and four of six off-diagonal cosine minima disagree with both `terminal_characterisation_small010b.json` and my direct recomputation from the raw terminal tensors (the means match; the minima are wrong by large margins, e.g. claimed 0.339 vs actual 0.692). These are descriptive, not verdict-bearing, but they are register numbers that cannot be traced to any artifact. (2) **The permutation test exists as two separate "PRE-REGISTERED" specs with materially different parameters** (seed, α, set list, matching rule, pool-relaxation rule); the code implements only the later one, and the earlier registration is referenced nowhere and never marked superseded — a register-integrity hole, made more pointed by the fact that the contrast set A1_tail landed at p=0.00620, between the two specs' thresholds (0.00556 new vs 0.00625 old).

The artifact-overwrite guard fixed by `e0bf0a7` is correct for what it covers, but `--arms` remains outside it: a bare `--tier full --arms A5` run would still silently replace the registered 150-record `results_full.json` with a 25-record file. The engine core loop is clean — deterministic, correctly lagged gate, no seed dependence (matching the recorded "seed is a no-op" claim).

## CONFLICTS/CONTRADICTIONS

1. **RESULTS_EXP010B.md vs its own committed artifact — five untraceable numbers.** `terminal_characterisation_small010b.json` (committed one minute before the results register, never modified) and my direct recomputation from the raw `terminals_small010b_*.pt` tensors both give: SB basin sizes **[6,5,4,3,3,3,1]**, off-diag cos min **SB 0.6921, S2 0.4983, S3 0.9700, S5 0.4410**. RESULTS_EXP010B.md:45 claims SB "7 (6,5,4,3,3,**2,2**)" and RESULTS_EXP010B.md:52–54 claims mins "SB 0.849 / **0.339** … S2 0.853 / **0.514**; S3 0.997 / **0.984** … S5 0.950 / **0.869**". The means all match; the four minima and the SB size tuple match *no* committed artifact (neither mean- nor last-vector cosines). Verdicts do not rest on these values, but the register asserts artifact-level numbers that the artifacts contradict.
2. **Two live "PRE-REGISTERED" specs for the same permutation test.** `PERM_TEST_EXP010c_SPEC.md` (2026-07-24, seed 2026, 8 testable sets, α=0.00625, frequency band = token-ID decile, mandatory pool-relaxation below 50 candidates, global anisotropy context statistic) and `EXP_010c_PERM_SPEC.md` (2026-07-25, seed 20260725, 9 testable sets incl. a new A1_tail contrast, α=0.00556, band = merges-rank//5000, no relaxation rule). The code and results implement only the later. The earlier spec is referenced by **no file in the repo** (grep confirms) and carries no superseded/withdrawn marker; both still read as pre-registrations of "Planned controls item 1". Two consequences of the switch were live in the executed run: the ` simultaneously` pool (43 candidates) would have triggered the old spec's relaxation rule; and the contrast set A1_tail's p=0.00620 falls between the two thresholds (fails at 0.00556, would pass at 0.00625 — though A1_tail only exists as a set in the new spec). The word-arm verdict (A4 passes at p≤0.0019) is robust to either registration.
3. **Minor**: RESULTS_JLENS_MEDIUM.md:293 states "the ATR engine does not prepend BOS." The engine passes raw prompt strings to `model.run_with_cache` (atr_engine2.py:309, 342), and transformer_lens's default for GPT-2 models is `prepend_bos=True`; unless the pinned TL 3.5.1 differs, this deviation note has the BOS convention backwards (inconsequential to the census numbers, which never touch the ATR engine).
4. **Not a contradiction but easily conflated**: Small converges 18/25 with ` Divine`×7 in EXP_010d (Medium's registered subset) vs 14/25 with ` Divine`×11 in EXP_010b SB (its own subset) — different prompt subsets; both internally consistent.

## RED FLAGS

1. Register numbers with no artifact provenance (item 1 above) in an otherwise rigorously cross-checked results file — suggests at least one table row was written from memory or from an uncommitted scratch computation, in a repo whose whole discipline is "committed artifact = authority."
2. Silent double-registration of the permutation test with materially different parameters and no supersession note (item 2 above). Whatever the intent (likely an honest rewrite the next day), the register as committed permits after-the-fact spec selection, and one threshold-sensitive outcome (A1_tail) sits exactly in the gap.
3. Residual overwrite hole `--arms` in run_exp010c.py's guard (Claims item 7) — the exact failure mode the guard was built for ("observed, not hypothesised — it happened twice", run_exp010c.py:342–343) remains reachable through the one flag the variant list omits.
4. The committed `permutation_results.json` does not carry the `input_sha256` attestation that the current script writes and the spec addendum describes — the provenance chain for the recorded run rests on the spec/RESULTS text, not the artifact itself.
5. Reproducibility of the EXP_010b gate and all prompt derivations depends on an external, mutable repo (`ATR_STAGE1_REPO` / lucier) that is not vendored; only the gated-results zip is committed. `derive_prompts.py:23–25` also hardcodes a developer path as fallback.
