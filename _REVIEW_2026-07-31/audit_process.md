# Process & Collaboration Health Audit — ATR_research (earlyprototype/atr_research)

## VERDICT

The science hygiene of this project is unusually good; the process hygiene is structurally broken, and every one of the eight failures under review traces to three root causes, not eight: **(A) concurrency without a ledger** — TC spawns parallel, mutually-invisible sessions under one shared GitHub identity against an open issue list, with no mandatory claim step and no allocator for hypothesis IDs, which produced the issue-#7 triplication, the H11 collision, and the double execution of EXP_010c-3; **(B) defaults inherited from the workspace and hygiene owned by nobody** — agents open PRs against whatever branch they were spawned on, merged branches are never deleted (I verified all 20 `claude/*` heads still live on origin), and every session's duty ends at PR-open or merge, which produced the PR #5 stranding, the PR #20 orphaning, four finished-but-open issues, seven zero-comment board threads, and a settled-but-open #38; and **(C) a human gate that is a fast merge button rather than a reviewer or decider** — TC merges results PRs in minutes without reading their threads (verified: PR #9 was merged 72 minutes after its own thread recommended closing it), never posts rulings in a form distinguishable from agent output, and left the #52 register dispute without a ruling long enough that an agent executed the contested resolution itself on 2026-07-31 (commit 371e754, verified) while the issue demanding a human ruling remains open. The fix is not more infrastructure — the board, registry, and reconciliation machinery already exist and worked whenever anyone used them — it is a short set of mechanical blocking checks plus two behavioral obligations on TC, detailed in the Action Plan.

### Phase 2 — Standing rules for agents (add to CLAUDE.md; CI-enforced where marked ⛔)

- **R1 — Base rule ⛔:** every PR bases on `main`. Stacked PRs require an explicit "STACKED ON #N" line in the body; CI fails any PR whose base is neither. Merged branches are deleted at merge. *(Prevents: #5 stranding, #20 orphaning.)*
- **R2 — Claim rule:** before starting issue N, comment `CLAIM <session-id>` on the issue and check open PRs referencing N; if claimed within 48h, stand down (the #6 stand-down comment proves agents can do this). *(Prevents: #7 triplication, EXP_010c-3 double run.)*
- **R3 — ID rule ⛔:** an in-repo `REGISTRY.md` — one line per H-number and EXP-number, owning spec, one-line statement. Claim by commit before first use. CI greps every PR diff for new `H\d+`/`EXP_\d+` identifiers absent from the registry and fails. *(Prevents: the H11/H11a/H12 collisions. This is issue #52 §11; implement it — the board-thread registry demonstrably does not work.)*
- **R4 — Closing rule ⛔:** a results-bearing PR must contain `Closes #N` or one line stating why not; CI warns on results-file changes with neither. *(Prevents: stale #11–#14.)*
- **R5 — Scope rule:** one experiment per PR; long-running jobs never run on a branch with an open dispute; artifact sets >50 files land as a separate artifacts-only PR referenced from the results PR, so the reviewable PR stays under review-tool limits. Every artifact-bearing tier commits its run log ⛔ (closes the #52 §6 audit-gap class). *(Prevents: the #10/#51 contortion.)*
- **R6 — Post-merge duty:** the session that merges (or lands the final commit) runs a 5-minute checklist before ending: issue closed, board thread closed with outcome, PR body accurate, branch deleted. Thread closure belongs to the *last actor*, not the opener. *(Prevents: stale trackers, zombie threads like #38.)*
- **R7 — Verification rule:** "verified" means completion evidence — exit code, artifact digest, reproduced number — never startup evidence. (Promote the onboarding thread's lessons into CLAUDE.md; this failure recurred in #23, #24, #27, and the `suffix` NameError.)

### Phase 3 — Rules for TC (two obligations, non-negotiable)

- **T1 — Merge discipline:** before merging any results-bearing PR, read its thread and its board thread; if both are silent, the merge comment must say `merging unreviewed`. Never merge within 2 hours of PR-open. *(Prevents: the #9 fiasco; makes silence costly without making the board a gate.)*
- **T2 — Decision SLA + signed authority:** anything an agent marks "owner ruling required" gets a `TC-RULING:` comment within 48h — even if the ruling is "delegated to session X, scope Y." Agents' side of the contract ⛔-adjacent: never self-execute a contested resolution without a `TC-RULING:` artifact to cite; file and wait. Human rulings are posted from the web UI with the `TC-RULING:` prefix (or GPG-signed commits) so delegation is verifiable — today it is not, and 371e754 happened in that gap. *(Prevents: the #52 self-execution; also assign one reviewer session per substantive results PR at spawn time, so board review is a job, not volunteering — prevents the zero-comment pattern on #48/#50/#54.)*

### The advisory-vs-blocking question — resolved

Split by who can evaluate the check. **Block mechanically** (CI): base-branch (R1), ID registry (R3), closing keyword (R4), run-log-with-artifacts (R5), plus a smoke run of the harness. Machines evaluate these perfectly; none can produce a false block that matters. **Keep human/peer judgment advisory but explicitly waivable** (T1): peer review, board CONCUR, scientific critique — a hard peer-review gate in a system where review supply is one volunteer agent would simply stall the pipeline or breed rubber stamps. The enforceable middle is: silence never blocks, but silence must be *named* at merge time. Six blocking checks and two TC habits cover all eight failures in this audit; anything longer will not be followed, and rules nobody follows are worse than none.
